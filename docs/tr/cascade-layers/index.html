Tam bir çeviri üzerinde çalışıyoruz.</strong> <!-- i18n-summary --></p> </blockquote> <p>Every rule shipped by Skeletonic is wrapped in a single CSS <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/@layer">cascade layer</a>. The compiled <code>skeletonic.min.css</code> starts with this declaration:</p> <pre><code class="language-css"><pre style="background-color:#0d1117;"> <span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">layer skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">reset</span><span style="color:#b48ead;">, skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">tokens</span><span style="color:#b48ead;">, skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">layout</span><span style="color:#b48ead;">, </span><span style="color:#b48ead;"> skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">elements</span><span style="color:#b48ead;">, skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">components</span><span style="color:#b48ead;">, skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">utilities</span><span style="color:#b48ead;">; </span><span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">layer skeletonic </span><span style="color:#c0c5ce;">{ </span><span style="color:#7d8a96;">/* …everything else… */ </span><span style="color:#c0c5ce;">} </span></pre> </code></pre> <p>Inside the layer, the cascade order matches the conceptual stack: reset → tokens → layout → elements → components → utilities.</p> <hr class="hr-text" data-content="Why"> <h2>Why this matters</h2> <p><strong>Anything you write outside a layer always wins.</strong> That includes your component CSS, your dark-mode tweaks, your one-off page styles — they take effect without specificity tricks, without <code>!important</code>, without trying to out-specify the framework's selectors.</p> <p>Try it. Drop this into any page that already loads Skeletonic:</p> <pre><code class="language-css"><pre style="background-color:#0d1117;"> <span style="color:#8fa1b3;">.</span><span style="color:#d08770;">button </span><span style="color:#c0c5ce;">{ </span><span style="color:#c0c5ce;"> background: hot pink; </span><span style="color:#c0c5ce;"> border-radius: </span><span style="color:#d08770;">0</span><span style="color:#c0c5ce;">; </span><span style="color:#c0c5ce;">} </span></pre> </code></pre> <p>The button override applies — even though Skeletonic's own <code>.button</code> selector targets exactly the same element. The unlayered rule wins because <strong>the unlayered cascade tier is always above any named layer</strong>.</p> <hr class="hr-text" data-content="Sub-layers"> <h2>Sub-layers</h2> <p>Skeletonic's six sub-layers let you target the framework with surgical precision. To override only the spacing tokens but leave the components alone:</p> <pre><code class="language-css"><pre style="background-color:#0d1117;"> <span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">layer skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">tokens </span><span style="color:#c0c5ce;">{ </span><span style="color:#c0c5ce;"> :root { </span><span style="color:#c0c5ce;"> --gr-h</span><span style="color:#d08770;">1</span><span style="color:#c0c5ce;">: </span><span style="color:#d08770;">5rem</span><span style="color:#c0c5ce;">; </span><span style="color:#c0c5ce;"> --cl-primary: </span><span style="color:#96b5b4;">hsl</span><span style="color:#c0c5ce;">(</span><span style="color:#d08770;">280</span><span style="color:#c0c5ce;">, </span><span style="color:#d08770;">80%</span><span style="color:#c0c5ce;">, </span><span style="color:#d08770;">45%</span><span style="color:#c0c5ce;">); </span><span style="color:#c0c5ce;"> } </span><span style="color:#c0c5ce;">} </span></pre> </code></pre> <p>Or to ship your own component layer that participates in the cascade <em>above</em> Skeletonic's components but <em>below</em> its utilities:</p> <pre><code class="language-css"><pre style="background-color:#0d1117;"> <span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">layer skeletonic, </span><span style="color:#bf616a;">app-components</span><span style="color:#b48ead;">, skeletonic</span><span style="color:#8fa1b3;">.</span><span style="color:#d08770;">utilities</span><span style="color:#b48ead;">; </span><span style="color:#b48ead;"> </span><span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">layer </span><span style="color:#bf616a;">app-components </span><span style="color:#c0c5ce;">{ </span><span style="color:#c0c5ce;"> .my-card { </span><span style="color:#7d8a96;">/* … */ </span><span style="color:#c0c5ce;">} </span><span style="color:#c0c5ce;">} </span></pre> </code></pre> <hr class="hr-text" data-content="Browser support"> <h2>Browser support</h2> <p>Cascade layers are a 2022 feature. Baseline support: Chrome 99, Firefox 97, Safari 15.4. <strong>All evergreen browsers and the last two years of Safari ship layer support.</strong> Skeletonic's <code>.browserslistrc</code> targets <code>> 0.5%, last 2 versions, Firefox ESR, not dead</code>, all of which support <code>@layer</code>.</p> <p>In the unlikely case you need to support an older browser, an unsupported browser will see Skeletonic's rules with their natural specificity — the rules still apply, you just can't override with unlayered CSS. That's a graceful degradation, not a breakage.</p> <p><a href="https://developer.mozilla.org/en-US/docs/Web/CSS/@layer">Read the @layer spec on MDN ↗</a> · <a href="/tokens/">Design tokens →</a> · <a href="/components/">Browse the components →</a></p> </div>
