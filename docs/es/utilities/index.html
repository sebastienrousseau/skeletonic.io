physical and logical</h2> <p>The spacing utilities follow a five-step golden-ratio scale (<code>xs</code>, <code>sm</code>, <code>md</code>, <code>lg</code>, <code>xl</code>). See <a href="/spacing/">the spacing ladder</a> for each step's resolved value. Logical (<code>-start</code>, <code>-end</code>) forms auto-flip in <code><html dir="rtl"></code>.</p> <pre><code class="language-text"><pre style="background-color:#0d1117;"> <span style="color:#c0c5ce;">.padding-{size} .margin-{size} </span><span style="color:#c0c5ce;">.padding-top-{size} .margin-top-{size} </span><span style="color:#c0c5ce;">.padding-bottom-{size} .margin-bottom-{size} </span><span style="color:#c0c5ce;"> </span><span style="color:#c0c5ce;">.padding-start-{size} .margin-start-{size} ← logical (RTL-aware) </span><span style="color:#c0c5ce;">.padding-end-{size} .margin-end-{size} ← logical (RTL-aware) </span><span style="color:#c0c5ce;"> .margin-auto ← centring helper </span></pre> </code></pre> <p>Where <code>{size}</code> is <code>xs</code> / <code>sm</code> / <code>md</code> / <code>lg</code> / <code>xl</code>. So <code>.padding-start-md</code> produces <code>padding-inline-start: 1.62rem</code> and auto-flips to <code>padding-inline-end</code> when the container's writing direction is RTL.</p> <h2>Group / clearfix</h2> <table> <thead> <tr> <th>Class</th> <th>Effect</th> </tr> </thead> <tbody> <tr> <td class="text-left"><code>.group</code></td> <td class="text-left">Adds a <code>::after</code> clearfix pseudo-element</td> </tr> </tbody> </table> <hr class="hr-text" data-content="Why both?"> <h2>Why class <strong>and</strong> attribute selectors?</h2> <p>Three reasons:</p> <ol> <li><strong>Authoring readability.</strong> <code><div center flex></code> is shorter and easier to scan than <code><div class="center flex"></code>. For pages with many utility-driven elements, the attribute form keeps <code>class</code> free for semantic state classes.</li> <li><strong>AI-generated HTML.</strong> LLMs produce attributes more reliably than long <code>class=" "</code> lists. Attributes are harder to typo.</li> <li><strong>No runtime cost.</strong> Both forms compile to the same selectors in the same CSS rules — no JavaScript, no preprocessor toggles. Pick either or both, freely mix.</li> </ol> <p>The attribute selectors are valid HTML — they are <em>custom data attributes</em> in the HTML5 sense. They render correctly, they round-trip through <code>outerHTML</code>, and they don't trigger any validator warnings.</p> <p><a href="/tokens/">Browse design tokens →</a> · <a href="/spacing/">Spacing ladder →</a> · <a href="/cascade-layers/">Cascade layers →</a></p> </div>
