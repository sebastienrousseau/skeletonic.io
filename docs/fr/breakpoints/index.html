Nous travaillons à sa traduction complète.</strong> <!-- i18n-summary --></p> </blockquote> <p>Most CSS frameworks expose a 4–5 step breakpoint ladder (<code>xs</code>, <code>sm</code>, <code>md</code>, <code>lg</code>, <code>xl</code>). Skeletonic does not.</p> <p>Instead, the <code>.container</code> width adapts through <strong>38 <code>min-width</code> media queries</strong> from <code>13.75em</code> (220 px) to <code>480em</code> (7680 px). The container gradually settles into a comfortable measure at every viewport size, so layouts work on phones, tablets, laptops, ultrawide monitors, and projection walls without you defining a single breakpoint yourself.</p> <hr class="hr-text" data-content="Why"> <h2>Why so many?</h2> <p>Two reasons:</p> <ol> <li><strong>There is no single "right" breakpoint</strong> for every project. Modern container queries finally fix this at the component level, but the page-level container still needs to choose a measure. Picking 38 small steps makes the wrong choice less wrong than picking 4 big ones.</li> <li><strong><code>em</code>-based queries adapt to user preference.</strong> Each query is <code>em</code>-relative — a user who has set their root font-size to 24 px gets larger thresholds automatically, so the layout reflows when <em>their</em> text needs more room, not when your designer thought it would.</li> </ol> <hr class="hr-text" data-content="Use"> <h2>You don't have to think about them</h2> <p>The 38 steps are a default the <code>.container</code> uses internally. If you write your own component CSS, prefer <strong>container queries</strong> for component-level responsiveness — they're now Baseline (Chrome 105+, Safari 16+, Firefox 110+):</p> <pre><code class="language-css"><pre style="background-color:#0d1117;"> <span style="color:#8fa1b3;">.</span><span style="color:#d08770;">card </span><span style="color:#c0c5ce;">{ </span><span style="color:#c0c5ce;"> container-type: inline-size; </span><span style="color:#c0c5ce;">} </span><span style="color:#c0c5ce;"> </span><span style="color:#c0c5ce;">@</span><span style="color:#b48ead;">container (</span><span style="color:#bf616a;">min-width</span><span style="color:#b48ead;">: 30em</span><span style="color:#c0c5ce;">) { </span><span style="color:#c0c5ce;"> .card { padding: </span><span style="color:#d08770;">2rem</span><span style="color:#c0c5ce;">; } </span><span style="color:#c0c5ce;">} </span></pre> </code></pre> <p>For page-level responsiveness, the standard breakpoints most teams reach for are <code>48em</code> (≈ 768 px, tablet portrait), <code>64em</code> (≈ 1024 px, laptop), and <code>80em</code> (≈ 1280 px, desktop). Skeletonic's 38-step ladder absorbs all of these, plus the cracks between them.</p> <hr class="hr-text" data-content="Range"> <h2>The full range</h2> <p>The lowest threshold is <code>13.75em</code> (220 px — feature phones, smartwatch detail views). The highest is <code>480em</code> (7680 px — 8K projection or billboard displays). Between them, every sensible web viewport size has at least one matching step.</p> <p>If you need to inspect the exact ladder, it's generated from a single <code>for</code> loop in <a href="https://github.com/sebastienrousseau/skeletonic-stylus/blob/feat/v1.1.7/src/stylus/layout/media-queries.styl"><code>src/stylus/layout/media-queries.styl</code></a>.</p> <p><a href="https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_containment/Container_queries">Container queries primer (MDN) ↗</a> · <a href="/cascade-layers/">Cascade layers →</a> · <a href="/components/">Browse components →</a></p> </div>
